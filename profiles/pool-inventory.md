# Pool optimizer version inventory reuse

Build each group's version inventory once and reuse it for its retained packages.

## Implementation

`PoolOptimizer::apply_removals_to_pool` lazily builds a version map for each
group with a surviving member. `BTreeMap` bulk construction sorts the entries
once and preserves the last pretty version for duplicate version keys.
Retained packages share immutable `Arc` maps. Overlapping memberships and
inventories from a previous optimization merge using copy-on-write, preserving
membership order and leaving the source inventory untouched. The public
`Pool::removed_versions_by_package` return type remains unchanged.

## Measurement

Baseline: `5b7592d4d43ace63b4551b1d6b56baabe305d6d4`.
Measured on 2026-09-28 with Rust 1.98.0, the repository's release profile,
Linux x86_64, and an AMD EPYC-Genoa processor. The baseline and candidate use
the same build commands and benchmark workloads. Compiler and test processes
were finished before the final wall-clock measurements.

The offline example measures the complete optimizer, including output-pool
destruction, for 300 package names with 100 versions each. `single` keeps one
candidate per name; `tied` adds three copies of the highest version, retaining
four; `replacement` groups four concrete package names under each virtual name,
also retaining four per group. Fixtures are constructed outside the timed region.
Each process validates a fingerprint of retained names, versions, and complete
inventories. Each scenario uses eight alternating before/after pairs, twelve
timed optimizations per process after an untimed validation/warmup run.

The Symfony Demo comparison uses copies of this checkout's `demo/composer.json`
and lockfile, a shared warm repository cache, and 16 alternating measured pairs
after one warmup pair. Platform requirements are ignored identically in both
binaries, and plugins/scripts are disabled. Dependency policy remains enabled;
this is an end-to-end dry-run update, not a network-free benchmark. Its pool
contains 4,910 entries, of which 4,073 are removed, and its resulting plan has
155 packages. Raw samples, binary checksums, and fixture/plan hashes are in
`pool-inventory.benchmark.json`.

### Final candidate results

| Workload / phase | Baseline median | Candidate median | Time change |
| --- | ---: | ---: | ---: |
| Single retained candidate | 13.443 ms | 13.039 ms | -3.0% |
| Four tied candidates | 25.430 ms | 13.572 ms | -46.6% |
| Four replacement providers | 20.951 ms | 15.511 ms | -26.0% |
| Symfony Demo: pool rebuild | 0.845 ms | 0.943 ms | +11.6% |
| Symfony Demo: entire optimizer | 7.036 ms | 7.246 ms | +3.0% |
| Symfony Demo: complete dry-run update | 428.993 ms | 415.837 ms | -3.1% |

The benefit is workload-dependent. The targeted synthetic cases improve
substantially, but Symfony Demo pool optimization is about 0.21 ms slower.
Its lower overall update median is not attributable to this change: the
measured optimizer phase regresses, and policy/network work remains in the
command. This is a candidate optimization for shared inventories, not a
demonstrated end-to-end performance win on the real fixture.

Callgrind whole-example instruction counts (including fixture setup and six
optimizer invocations) fell from 1,025,762,877 to 965,990,292 for `single`
(5.8%) and from 1,898,957,742 to 1,035,275,247 for `tied` (45.5%). These
are one-capture attribution checks, separate from the wall-clock samples.

Both final release binaries generated byte-identical lockfiles:
`b795a57358646cd139f529ed271062b7c438deddfaf4de5720998ca1ff790050`.

## Reproduction

Build at the baseline and candidate revisions, copying the example to the
baseline checkout and saving each binary before rebuilding:

```sh
mise exec -- cargo build --release -p riff-core --example pool_optimizer_benchmark --locked
target/release/examples/pool_optimizer_benchmark single 12
target/release/examples/pool_optimizer_benchmark tied 12
target/release/examples/pool_optimizer_benchmark replacement 12
mise exec -- cargo build --release -p riff --bin riff --locked
```

Alternate saved baseline/candidate binaries eight times for each synthetic case.
For the real fixture, set `RIFF_CACHE_DIR` to the same warmed cache and
`RUST_LOG=riff_core::solver::pool_optimizer=debug`, then run each saved CLI with:

```sh
riff update --dry-run --no-plugins --no-scripts --no-interaction --no-ansi \
  --ignore-platform-reqs -d /path/to/fixture-copy
```
