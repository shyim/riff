# Policy metadata cache benchmark

On 2026-09-05, caching a compact policy projection reduced warm update time from
584.7 ms to 367.5 ms (37.1%, or 1.59x faster) on Symfony Demo. Blocking policy
checks remained enabled. Mean user CPU time fell from 328.4 ms to 128.1 ms
(61.0%). Single-run peak RSS measurements fell from 230.0 MiB to 78.0 MiB.

| Workload | Before | After |
|---|---:|---:|
| Warm update, before-first order, 20 runs | 581.4 ± 20.7 ms | 366.0 ± 22.7 ms |
| Warm update, after-first order, 20 runs | 587.9 ± 26.2 ms | 369.1 ± 34.6 ms |
| Repeat install, 10 runs | 188.6 ± 8.1 ms | 186.6 ± 11.7 ms |

The uncertainties are sample standard deviations. Repeat installs showed no
meaningful change; this optimization targets metadata loading during updates.
The 168 policy cache files generated by this workload totaled 59,298 bytes.

## Change

Previously, advisory lookups loaded full historical package records after the
solver had already loaded compact filtered records. Capturing policy fields also
constructed a complete `serde_json::Value` tree for each repository response.

The new path captures only `filter` and `security-advisories`. It validates the
response envelope and scans version entries without allocating their contents.
The derived `provider-*.json.policy-v1.json` cache is keyed to the original
response's SHA-256 digest and is usable only while that response remains fresh.
Missing, malformed, wrong-version, or mismatched projections are rebuilt from the
source response. Stale or missing source data uses the existing repository load
path, retaining conditional requests and error handling. Explicit empty advisory
lists remain distinct from missing metadata, which may require an API fallback.

No policy checks or post-install behavior were disabled by this change. The
malware summary request still runs with its existing freshness behavior. Its
network latency and repeated constraint evaluation remain optimization candidates.

## Reproduction

Baseline: commit `4a40d9554d0d933234a4534a29e393dce0f2d7d4`, saved release binary
before editing. Candidate: this working-tree change, built with
`mise exec -- cargo build --release -p riff --bin riff` (default mimalloc enabled).
Environment: Rust 1.98.0, PHP 8.5.10, Hyperfine 1.20.0, Linux x86_64,
AMD EPYC-Genoa processor. No compilation ran during timed measurements.

Fixture: Symfony Demo commit `920d86dc809f837543cb519d3df5b364a2c36577` (153
locked packages). All operations used temporary project copies and private cache
directories. The before/after caches were copied from the same populated source
cache, preserving modification timestamps. Each update command received three
warmups, then 20 runs; the second set reversed command order. Repeat installs
used two warmups and 10 runs per binary.

```sh
RIFF_CACHE_DIR="$benchmark_cache" COMPOSER_HOME="$benchmark_home" \
  "$riff_binary" update --dry-run --no-scripts --no-plugins --no-audit \
  --no-interaction --no-progress --no-ansi -d "$benchmark_project"
```

Use `install` instead of `update --dry-run` for the repeat-install comparison.
The fixture retains its original lock and an installed vendor directory while
timing updates. `--no-audit` skips the post-operation audit; it does not disable
advisory/malware blocking. Neither measurement uses `--no-blocking`.
Peak RSS was measured separately with `/usr/bin/time -v`, once per binary.

Raw Hyperfine samples and peak RSS readings are in
[policy-cache.benchmark.json](policy-cache.benchmark.json). All times in that
JSON are seconds, except the explicitly named KiB memory fields. These results
describe one fixture and host; network and scheduler variation still apply.

## Validation

- `cargo test --workspace --all-targets --locked`: 2,231 passed, 10 existing ignored.
- Clippy with all workspace targets/features and `-D warnings`: passed.
- Six policy projection/cache regression tests cover cached advisory and malware
  results, partial/full advisory validation, unaffected versions, empty versus
  missing metadata, duplicate fields, invalid response envelopes, source changes,
  corrupt projections, orphaned projections, and expired-source refresh/errors.
- Before/after dry-run output matched byte-for-byte.
- Separate `update --no-install` runs generated byte-identical lockfiles:
  SHA-256 `17a9aa1905344bc62909e0a356787f01dd4ed991e60e41033c93af2cf6258d3c`.

This verifies equivalence to the baseline Riff behavior on this fixture; it does
not resolve the previously observed Composer/Riff update-plan difference.
